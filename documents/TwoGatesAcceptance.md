# 用 two-gates 定义浮点变换的可接受性

入口是 [check_two_gates.py](../scripts/check_two_gates.py)，统一配置在
[two_gates_config.py](../experiments/floating_point/two_gates_config.py)。默认每个可运行的
“规则 × 精度配置”固定运行一次，峰值原分布输入预算为 `2**32` 组；三条指定 FP32
规则额外使用 `2**25` 组近零提议，两道门共用已执行的输入和 P/Q 输出。
运行命令、依赖与证据格式见 [实验指南](../experiments/floating_point/README.md)。

## 原子假设与 Lean 的职责

Two-gates 为指定分布、输入域、精度和后端下的原子改写提供实验依据。
Lean 负责检查这些假设怎样接到实际源码和组合推导，公开结果仍是 `original ≡[R] candidate`。
统计接受不会把不成立的浮点精确等式变成严格定理，也不会自动提供整个 kernel 的误差界。
实数数学正确性、索引、内存安全、归约和调度仍须分别证明。

基本关系是标量表达式对；完整 softmax、Welford、LayerNorm 等不是一条新的准入原子。
当前目录的严格证明与实验规则分类见
[CurrentAdmission.lean](../VeriTile/Triton/Float/CurrentAdmission.lean)。
实验记录不自动回写 Lean 准入，也不把未测精度或域外配置算作通过。

## 冻结的执行契约

| 项目 | 必须记录的内容 |
|---|---|
| 程序 | 原始与候选表达式、源码散列、每个实际执行形状的 PTX |
| 精度 | 输入、逐操作计算、显式转换、累加和输出精度 |
| 输入 | 分布、参数、量化方式、原有输入域、独立随机流及种子 |
| 抽样 | 总输入预算、近零库预算、层概率、提议密度比、混合计数 |
| 统计 | 均值、分层方差和标准误、两种实际误差峰值、筛选与排除数 |
| 后端 | GPU、计算能力、驱动、CUDA、Torch、Triton、NumPy、mpmath、编译选项 |
| 证据 | 所有执行分块统计、输入输出指纹、固定原始审计、CPU 重放结果 |

分块尺寸只控制工作和内存；统计预算独立指定。执行前冻结配置和混合计数，
不按第一次通过早停，不因为失败追加样本，不从重复运行中挑选较好的种子。
`--resume` 复核后保留完成项，未完成项从同一冻结种子重启。

默认输入是各操作数独立 `Normal(1,1)`，先在 FP64 生成再按源程序转换。
P/Q 执行声明的 cast、运算顺序、FMA 设置、输入域与 oracle。
整数计数配置使用有界整数或常量输入。

## 均值门：全库加权

对原有域内、P/Q/oracle 均有限的输入，令

```text
delta = (candidate - reference) / ULP_output_format(original_oracle)
```

ULP 在原 oracle 绝对值舍入到输出格式后取得；零使用最小次正规间距，最大有限值
使用向内间距。有限 oracle 超出输出格式范围时只截住间距查询，不修改用于误差的 oracle。
FP64-work 除法使用编译的残差 oracle。

主目录 FP32 的 `CANCEL`、`ADD-ASSOC`、`MUL-DISTRIB` 在指定 `Normal(1,1)`
分布下使用已检查的分层设计。近零层半宽为 `2**-12`，分别按舍入后的 `a`、
量化前的三项和、量化前的两个加数之和划分。高斯正交坐标保持其他方向的条件分布。
CANCEL 的提议按 FP64 舍入单元宽度取样，使用 FP64 生成再转 FP32 的边界。

设目标层概率为 `p0,p1`，近零提议为 `q0`，层内目标密度为 `f0`，权重 `r=f0/q0`：

```text
mu = p0 * mean(r * delta_near) + p1 * mean(delta_rest)
SE^2 = p0^2 * sample_variance(r * delta_near) / n_near
     + p1^2 * sample_variance(delta_rest) / n_rest
```

样本方差使用各层的 `n-1`。使用整个样本库，不自归一化权重，不截断误差尾部。
其余配置使用原采样器、单位权重和有效样本的普通均值/样本方差。
必须满足 `abs(mu)+5*SE <= 0.05 ULP`。这是项目验收统计量，未宣称已经证明其
对所有重尾分布的覆盖率。估计所需的任一层少于两个有效样本时为 `INCONCLUSIVE`。

## 峰值门：恢复原分布后取未加权最大误差

共用库含 `A=2**25` 组近零提议和 `N=2**32` 组补集条件样本。
在读取任何程序误差前，用独立 CPU 随机流抽取 `K~Binomial(N,p0)`。
近零提议以 `r/1.001` 的概率接受，取前 K 个接受点；补集取前 `N-K` 个点。
选择只依赖密度比、独立均匀数和提议顺序。

接受—拒绝恢复近零条件目标分布，二项式层计数恢复目标混合分布。
在理想密度模型下，除已界定的有限供给耗尽事件外，得到的无序样本多重集可与
N 组原分布独立样本耦合。峰值对顺序不敏感，因此不需要实际打乱数组。
这保留了两个误差最大值及其比值的联合统计含义。
FP64 重构和机器 RNG 的精确离散概率没有因此获得形式化认证。

在同一选择集上分别取

```text
reference_peak = max(abs(reference - oracle))
candidate_peak = max(abs(candidate - oracle))
candidate_peak <= 10 * reference_peak
```

原实现要求残差 oracle 时使用原残差误差。两个峰值可以来自不同输入。
不计算逐点误差比的最大值，不给实际误差乘重要性权重，也不用有偏全库的参考峰值
放大验收门槛。全库峰值单独保留作诊断。候选峰值为零时比值为零；参考峰值为零
而候选非零时比值为无穷并失败。

近零供给不足时记录 `INCONCLUSIVE`，不截短 N、不改 K、不重抽 K。
三条加权规则的原域完整且有限，成功恢复后恰好有 `2**32` 组有效峰值输入。
其他配置保留原有域和非有限筛选，分别报告 `peak_drawn` 与 `peak_valid`，不补抽排除项。

## 验收状态和证据边界

只有固定预算完成且两道门均通过的正式运行才是 `ACCEPT`。
完成但数值门未通过是 `REJECT`；供给/有效样本不足是 `INCONCLUSIVE`；
不支持的精度是 `UNSUPPORTED`；执行或证据错误是 `ERROR`。
小型检查始终标为 `SMOKE_ONLY`，不会进入接受名单。

CPU 重放核对全部分块、总预算、冻结抽样身份、源码与 PTX 散列和最终判决。
固定位置、层边界、活动近零接受步骤及部分前缀分块必须保留原始审计。
审计独立重算分层权重、选择掩码、统计量及峰值；三条加权源程序的首个层内执行
还与 NumPy 的原始 FP32 表达式及 FP64 oracle 对照。

非原始审计位置保留完整分块统计和指纹；不宣称所有数十亿输入都已在 CPU 上重新执行。
有限采样通过不证明全域 IEEE 位值相等或全域误差界。GPU 执行和 oracle 仍属于受信实验边界。

报告必须绑定实际测量的源码、精度、输入域和判决统计量。
Lean 准入记录中的规则范围必须与证明的使用范围对应。
