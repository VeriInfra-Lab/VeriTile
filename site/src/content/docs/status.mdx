## Inspect the evidence

Use the [searchable proof coverage table](/VeriTile/proofs/coverage/) to inspect
each kernel's theorem, source functions, numeric model, assumptions, and gaps.

The [final validation guide](https://github.com/VeriInfra-Lab/VeriTileBench/blob/main/documents/bench/current_source_acceptance.md)
provides the current commands. The [historical contract review](https://github.com/VeriInfra-Lab/VeriTileBench/blob/main/validation/archive/contracts.json)
preserves the earlier formulas, assumptions, numerical dependencies and scope. Source counts alone do not establish proof completion or native execution.

The website build counts source files. It does not rerun the Lean proof
audits or certify a new audit result.

## Reproduce the checks

From the **VeriTile** root:

```bash
lake build
bash scripts/check-core-examples.sh
bash scripts/check-artifact.sh
```

The core [workflow](https://github.com/VeriInfra-Lab/VeriTile/actions/workflows/core.yml)
builds the library and three source/Real/FP example pairs on PRs and main
pushes. Its nightly/manual artifact gate builds the full library, checks
placeholders, allowed axioms and the manifest, resolves documented APIs, and
independently replays proven library-manifest targets and their dependencies.
It does not select every unused theorem in every library module.

From a **VeriTileBench** checkout, run
`bash scripts/bench/audit_tritonbench_g.sh` for the complete corpus checks.
The separate [benchmark workflow](https://github.com/VeriInfra-Lab/VeriTileBench/actions/workflows/bench-audit.yml)
has source/smoke and public-entry checks on PRs/main pushes; its daily/manual
full audit selects all retained modules, including helper theorems.
The site's coverage table reads the pinned benchmark revision in
`site/src/lib/benchmark-source.json`; a website build is not a new proof audit.

## Upstream bug reports

Two reports to PyTorch illustrate silent failures in generated kernels:

- [Pooling and reduction: incorrect batch stride (#179931)](https://github.com/pytorch/pytorch/issues/179931).
  A generated reduction used 3200 as the batch stride instead of the actual
  3185, producing shifted reads and potentially out-of-bounds accesses.
- [Slice-scatter backward: collapsed gradient dimension (#180164)](https://github.com/pytorch/pytorch/issues/180164).
  A zero stride inherited from a broadcast tensor collapsed an iteration
  dimension; correct forward outputs masked incorrect gradients.

The reports contain reproduction details and the latest resolution.
