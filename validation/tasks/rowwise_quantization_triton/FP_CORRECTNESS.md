The accepted pre-llrint row stage now has an independent typed value contract and a concrete software bit interpretation in `FPCorrect.lean`. Both prove successful source execution, active row readback, the scalar maximum store, and preservation outside both write sets. The ordinary requirements are a nonempty reduction width and distinct output regions.

The source retains undefined masked loads, clears inactive lanes before the maximum, takes actual floating absolute value, divides and multiplies in FP32, and rounds the stored maximum to FP16. Its independent output formula reads the initial memory. The bit interpretation uses separately rounded `FP.div` and `FP.mul`; the FP16 store directly rounds the decoded FP32 value to binary16 and does not treat narrowing as identity. FP16 payloads occupy the low sixteen bits of the explicitly typed carrier cell.

`source_load_prefix` checks the existing source's load/address/mask prefix. `source_abs_node` checks the corrected floating abs operation. The historical mathematical source used a comparison/subtraction expansion for abs and erased the half store; that mathematical projection is not a proof of bit equivalence. The old real-valued proofs remain separate, with their statements unchanged.

The original accepted scope stops before CUDA `llrint` and the final int8 output. These operations are still outside this stage. The bit maximum uses encoded ordering and least-index ties; NaN and signed-zero behavior, division lowering, FP32/FP16 conversion, compiler fusion, launch/index mapping, and device configuration still require a native binding. No GPU experiment was run in this environment. Passing a finite probe suite will be reported as experimental evidence, not a universal hardware proof.
