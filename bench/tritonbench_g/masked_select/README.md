# masked_select

Current public entry: `RawBitCorrect.lean::six_format_raw_bit_correctness`, with the [reviewed proof package](../../review-checkpoints/2026-10-15/masked-select-raw-bit-closure/README.md). It covers the original complete seven-statement mask/prefix consumer with five floating word formats and int64 payload transport. RawCell.int remains arbitrary Int; the transport instance proves all signed64 payload patterns without narrowing general memory.

All selection/prefix/payload reads use initial memory, including output aliases. Complete encoded/decoded memory, success and frame are proved; readback uses only old selected in-bounds injectivity. Three modules and 25 named checks passed independent compilation; one new public declaration is counted. See [current integration](../../review-checkpoints/2026-10-15/masked-select-software-metadata/README.md).

Prefix is still Nat: zero minus one saturates to zero. This is not machine signed64 negative-address semantics. Host cumsum, pointer/overflow, byte ABI, native64 and GPU execution remain unproved.

## Historical typed-carrier proof


Source: `masked_select.py` (TritonBench-G v1).

`FPCorrect.lean::masked_select_typed_correctness` executes the actual seven
source statements with fp16, bf16, fp32, f8e4, f8e5 or int64 payloads, plus
an abstract `.real` channel generated by the float64 source annotation.
That extra channel has no native 64-bit floating storage binding.
It proves success, independent source-to-output readback at prefix-derived
addresses, and preservation outside the actual selected write set. Inputs,
selection masks and prefix entries are read from the initial memory snapshot;
input/output aliases are permitted. No output values are assumed.

The only readback address condition is injectivity among selected in-bounds
lanes. Unselected prefix entries can repeat. Prefix-sum construction is the
existing host/stage boundary; prefix metadata remains the accepted Nat model.
The theorem does not add a positivity, contiguous-stride, all-selected or
finite-floating-value restriction.

`Proofs/TypedCopy.lean::floating_source_projection` recovers the exact existing
source after floating dtype erasure. `source_control` retains every control
and metadata statement for all seven types; `int64_payload_dtype` checks the
integer load/store channel. The opaque floating model never uses real-number
arithmetic; frontend `.real` channels hold opaque payloads. Precision-tagged
fp32 loads are modeled, but unqualified `.real` is not evidence for fp64.
The raw fp32 load backend is defined in `kcache_copy_triton/Proofs/TypedCopy.lean`.
There is no floating arithmetic/rounding law to test for this copy.

`masked_select_int64_bits` proves preservation and re-encoding of every
`BitVec 64` input. `masked_select_bit_success` gives a nonempty fp32 execution
with signaling-NaN and negative-zero payloads, a repeated prefix on an
unselected lane, an out-of-bounds lane and neighboring framed output cells.
These are Lean proofs/witnesses, not GPU measurements.

Existing finite-region and launch obligations remain in `MaskedSelect.lean`.
Machine-address overflow, the host prefix-sum producer and CUDA refinement
are not claimed by this payload transport proof.
