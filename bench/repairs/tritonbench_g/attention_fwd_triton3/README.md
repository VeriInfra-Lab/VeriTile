# attention_fwd_triton3 whole-source repair

This separate candidate fixes actual signed integer overflow in a valid FP32 call. It does not replace the original source or accept the original task. The original progress row and its historical evidence remain unchanged. In particular, a lazy negative tensor view is not a new source defect: the selected interface consumes raw FP32 storage after lazy negative/conjugate metadata has been resolved.

## Defect and minimal change

Take Q=zeros([1,1,1,16]), K=zeros([1,1,2,16]), V=ones([1,1,2,16]), BM=BN=64, scale=.25, INIT=END=true, ordinary window offset=size=2147483647, and correctly padded O/M/L. Row zero keeps only key one. The original int32 upper numerator `63+2147483647+64` wraps to -2147483522, so the loop is skipped: O=0 and M=-inf, whereas the retained key gives O=1 and M=0. The original and repaired CPU-interpreter receipts, saved original TTIR and `Defect.lean` independently expose this arithmetic. The carry-base example `65534*32832=2151612288` is an additional arithmetic witness; it does not claim a giant runtime allocation or a GPU test.

There are six source edits: widen the inner `start_m`; widen `off_hz`; type the lower zero and upper `N_CTX` clamp as int64; narrow the initial K and V block-pointer `lo` argument back to int32. The active `lo` lies in [0,NK), so this narrowing is exact. An inactive initial pointer is never accessed. Outer Q/O row offsets keep their required int32 block-pointer ABI. Floating expressions, API, `_forward`, module globals and the one-retry handler are unchanged. Only the automatically executed bottom CUDA harness is omitted from the importable candidate.

## Selected input and runtime contract

Q/K/V/O/M/L use FP32 storage. Shapes are Q=[Z,H,NQ,D] and K/V=[Z,HK,NK,D], with positive H/HK and HK dividing H; the GQA head is `h // (H // HK)`. D is a supported source block dimension (16/32/64/128 for the saved profiles). Q/K/V/O have independent nonnegative element strides. O satisfies the ordered stride hierarchy in `Geometry.Ordered`, which proves output address injectivity. M/L are contiguous flat raw workspaces. All six physical allocation regions are disjoint in this package; read-only inter-region aliases are not included in that physical theorem.

O/M/L have room for `rounded=ceil(NQ/64)*64`, independently of the current persistent BM. All BM padded rows of O and M are stored without a query-row mask; L is also stored when END=false. Zero tensor extents require zero span. The abstract source/Real and raw graph statements permit empty grids, empty NK and no-loop calls. An actual zero-grid invocation additionally uses the runtime's ordinary zero-grid launch behavior; no new zero-grid driver experiment is claimed.

The machine contract has signed32 offset/size, NQ and NK at most 2^31-65, rounded below 2^31, Z*H at most 65536, and positive BM/BN at most64 with BM dividing64. Runtime launch limits may be stricter and must hold. Tensor base addresses, byte spans and each formed active base/stride/address calculation fit the selected runtime signed integer/pointer ABI. `CallMachine.complete`, `advance32` and `Machine.tail_and_backedge` prove the widened source numerators, carry offsets, narrowing and loop-counter facts. This is not a formal general compiler or CUDA memory-safety theorem.

The successful call uses the actual current module globals. They start at64, become32 after one first-attempt OutOfResources, and can become16 on a later call. The wrapper halves once and retries once; a second failure escapes while the halved globals persist. Other exceptions do not trigger retry. Resource failure is before kernel stores under the normal compilation/runtime contract. The repair never resets or clamps these globals. For later configurations, the complete source and generic graph are available under their stated contracts; only the six listed profiles have concrete native replay evidence.

## Whole-source semantics

The full typed source is `Kernels.source`, using the inherited `FP32Source.original`. `Kernels.real_erasure`, in `Proofs/Erasure.lean`, identifies its complete erasure with `Host.Call.source`. The canonical source entry imports only source definitions and metadata; its correctness consumers import the erasure helper. `Correct.correct` executes the complete finite grid from all six actual initial arrays, gives every active O/M/L value, and proves the exact memory frame. `Host`, `Ownership`, `Flat`, `Return` and `Physical` prove affine bounds, unique ownership, output coverage, actual flat bytes and the public view. The dependency closure pins every inherited repository source, including `bench/tritonbench_g/attention_fwd_triton3/Correct.lean`, `Kernels.lean`, `Proofs/FP32Profile.lean`, `Proofs/RealContract.lean`, `Proofs/RealFormula.lean`, `Proofs/RealKeys.lean` and their imports. The earlier whole-task review is an unaccepted review entrance, not an accepted-original premise.

The ordinary window is `0 <= row-key+offset < size`; complement is the older side `row-key+offset >= size`, not the Boolean complement of the ordinary interval. The source uses base2 scores with literal 1.4426950408889634. The independent Real target is inherited `Correctness.expected` / `RealFormula`: it combines the initial carry and the exact retained padded key sequence. `INIT=false` reads raw O/M/L from the same initial memory; arbitrary raw continuation is permitted. `END=false` stores raw accumulator, center and denominator. `END=true` stores O=a/l, M=m+log2(l), and preserves every L byte. A normalized END result is never silently reinterpreted as raw carry.

The inherited Real model has `WithBot` centers, weight zero when either center is bottom, total Real division/log, and zero as the memory representation of bottom. It is not IEEE arithmetic. In an all-masked INIT block, native NaN-alpha repair retains l=1 while the inherited Real transition can produce l=0. Executing an empty block and executing no loop are therefore different Real cases. The two models have separate statements; no native-to-Real equality or error bound is claimed.

`Physical.snapshot` assembles the actual little-endian bytes of all six input regions. Full native output words are computed before their bytes are stored. Every other byte is unchanged; in END calls, this includes all L. The END public O view is `o[:,:,:NQ,:].contiguous().to(q.dtype)`, with logical values/shape preserved. It may share or allocate storage, so fresh O identity is not promised. M/L are the original objects, and END=false also returns the original O. `Return.two_calls` and `Physical.two_calls_equiv` use the actual first final memory for the second call. `HostRetry.invoke_*` connects the persistent retry transition to the chosen complete byte execution.

## Native arithmetic and physical writer choices

`Raw.Ops` has exactly nine local numerical families: add, sub, mul, div, max, exp2, log2, FMA, and one coordinate of a fixed K=8 matrix instruction. The matrix family has five finite forms: MMA m16n8k8 and WGMMA m64n{16,32,64,128}k8, all with the emitted f32/tf32 operand signature. Matrix rows/columns and eight input lanes are explicit. No arbitrary-size dot/reduction or whole-output callback appears. The fixed log2 leaf is the saved compiler's scalar polynomial and exceptional branches, with one L-word input and a pinned body hash; it is not an assumption about an arbitrary row function. There is no literal callback: 1.4426950408889634 has exact native bits 0x3fb8aa3b. No separate host-scale numerical family is used because `sm_scale` is a caller-supplied scalar with the normal fp32 argument ABI.

The saved PTX has no explicit `cvt.*tf32` instruction. The matrix leaf denotes the actual fixed emitted TF32 instruction on its raw operand words, including its prescribed operand interpretation, rounding and exceptional behavior; it is not an exact FP32 dot. A lowering with additional conversion instructions needs a new binding. The denominator uses an FMA, PV uses the scaled previous accumulator as the live matrix seed, and no-window/even profiles fuse score scale-minus-max. The raw graph represents those operations directly. Every consumer retains its ordered reduction tree: no FP addition/max commutativity, associativity or cross-writer bit equality is assumed.

The compiler repeats scalar shared writes. For BM64, four lanes of one warp can write the same aligned b32 address; a finite lane index selects its permitted writer. BM32 has two replicated warps: each has a finite lane selection, and each read byte selects a replica. This conservative uniform-race model is grounded in CUDA's unspecified same-warp final writer and PTX8.7's scalar decomposition and uniform-size race rules. BM16 uses a checked shuffle to lane zero and no such scalar shared choice. M and L choices are independent at each actual CTA/row. O collisions are checked identical expression graphs. The barrier before shared readback is checked. Choices contain indices only, and bytes come solely from their fully computed candidate words; there is no arbitrary final-word oracle. Equality under the nine local laws holds for every choice. Different permitted choices need not yield equal bits.

## Executed checked boundary

`_forward` now requires six supplied, resolved, ordinary strided CUDA FP32 tensors on one device. Q has shape `[Z,H,NQ,D]`, K/V have shape `[Z,HK,NK,D]`, D is 16/32/64/128, and positive HK divides positive H. Inputs retain independent nonnegative strides. O has exactly `[Z,H,ceil(NQ/64)*64,D]`; M/L have the corresponding contiguous `[Z,H,ceil(NQ/64)*64]` shapes. The checked output stride hierarchy establishes injectivity for every padded store. All six live intervals must be disjoint. No input copies, view resolution, or padding is performed.

The checks compare every declared view span with the actual storage capacity and check data-pointer natural alignment, signed64 byte displacement, and unsigned64 absolute formed-address bounds. The conservative formed envelope includes padded Q/O lanes, final K/V advances, and initial window block-pointer formation even when the window is empty. Signed32 context/window/launch guards derive the accepted `CallMachine.ABI`; an additional initial-window bound keeps even inactive K/V narrowing representable. `Contract.lean` derives `Valid`, `Allocated`, disjoint placement, aligned finite addresses, and the exact widened source coordinate expressions from these checks. It assumes no source-index, alignment, padded-address, or unique-writer conclusion.

`Checked.checked_real`, exported by `Correct.lean`, retains the complete precision-erased source execution, independent six-input mathematical formula for all written O/M/L cells, and full flat-memory frame. `Checked.checked_native`, exported by `FPEquiv.lean`, retains the exact full native output bytes/frame and caller-visible return behavior for the six named saved profiles; `checked_equiv` defers only the accepted nine local numerical instruction families. Those profile restrictions remain explicit. Other valid flag combinations and retry configurations use the accepted ordinary source/compiler schedule boundary; no additional concrete compiler coverage is claimed.

The original module globals are preserved. A first `OutOfResources` halves both, validates the selected configuration, and retries once. The second failure escapes and leaves the halved globals in place. The supported block configurations are 64, 32, and 16; leaving that domain rejects without resetting or clamping the globals. END retains its original `slice.contiguous().to(q.dtype)` return behavior, M/L identities, and END=false O identity.

Validation: the current 70-module closure, including the checked public readers, compiles. The actual Triton source interpreter passes 25 controls covering complete O/M/L/frame, INIT/END, ordinary and older-side windows, BM16/32/64 tails, GQA, empty keys, all-masked cases, and the signed32 overflow witness. The actual host wrapper passes 43 metadata/pointer/storage/retry controls. These are CPU/source checks, not GPU execution or native numerical conformance.
