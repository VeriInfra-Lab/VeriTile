# Repaired single RMS matmul with optional rotary

`rms_rbe_matmul_repaired.py` preserves the original single-projection API, fixed epsilon `1e-6`, theta `10000`, 16×64×64 tile, four warps, four stages, and FP16/raw-int8-E5M2 output formats. The original benchmark file is unchanged.

`Contract.InputContract` is the named admission contract, with bidirectional guard proofs in `Proofs/InputContract.lean`. X is contiguous resolved aligned FP32 CUDA storage of shape `[B,M,K]`, with K positive. Weight is contiguous FP16 or int8 storage of shape `[N,K]`. The original RMS vector has shape `[K]` and may be FP32, FP16 or int8. All inputs share the input device. Head count and head width are exact positive Python ints, head width is even, and `N = heads * head_dim`. `use_rbe` must be an exact bool. Start position accepts Python int, including bool, in signed int64; a nonempty rotary call also checks the final padded 16-row position. The output has shape `[B,M,heads,head_dim]`, the weight's dtype, and the input device.

The source's original `rms_w.to(weight.dtype)` runs only when the dtypes differ. In particular, conversion to int8 is a numeric signed-int8 conversion followed later by E5 payload reinterpretation; those are separate operations in the proofs. No other normalization copies, device transfers, or layout conversions are introduced. Offsets, empty batch/row dimensions, and noncanonical unused singleton strides are admitted. Overlapping read backings must share both their base pointer and dtype. Same-base, same-dtype aliases remain admitted, including tensors with distinct storage offsets. The canonical guard continues to reject shifted-base imported overlaps and mixed-dtype overlaps. The physical input binding reads one shared byte heap and derives the admitted aliases from their actual addresses.

The kernel repairs all K-tail masks, FP32 weight promotion for the selected FP32 input dot path, integer widths, and overflowing ceil-division numerators. It normalizes the FP32 accumulator and rotates adjacent pairs before the sole final output conversion when requested. Frequencies restart at each caller-selected head boundary. Empty batches/rows skip the launch. No 32-bit shape or 65,535-grid cap is added; successful ordinary Tensor, allocation, view and launch APIs are the boundary. Shared launcher limits are separate from active source addressing. Masked inactive pointer expressions are not required to fit signed arithmetic.

`Kernels.lean` is source-only. The current `Kernel*` proof closure follows the actual shared typed source: prefix, dynamic K-block loop, normalization, optional reshape/split/join rotation, final cast and stores. `KernelGrid` composes the original rectangular launch and `KernelCoverage` proves every logical output coordinate is covered, including tail programs and empty dimensions. Historical event-model declaration snapshots are retained in `Proofs/HistoricalCorrect.lean.txt` and `Proofs/HistoricalFPEquiv.lean.txt`; the current public files do not import them.

Public specifications are `rms_rbe_matmul_repaired_real_returns` and `rms_rbe_matmul_repaired_fp_returns`. They derive successful source execution and returned metadata directly. The independent Real target is a finite-sum RMS projection followed by optional adjacent rotation, reading original physical input words and the wrapper's scalar RMS conversion. The native reference expands the ordered input-only expression into scalar operations, a complete reduction tree, and complete K8 MMA instruction lists. It preserves the two-argument source dot followed by its outer FP32 add; the compiler's observed carry absorption is an explicit selected choice, with no split/fused equality assumption. Rotary FMA operand/sign order, powi2's two FTZ multiplies, final format conversion and raw signed-byte E5 decoding are explicit. Selection sees expression shapes with floating words, E5 payloads and runtime signed positions erased.

`KernelBinding.Preparation` contains only original-storage preservation and the per-element Tensor.to conversion. Actual physical reads honor base pointers, offsets and admitted aliases. `KernelPhysical.store_bytes` derives the 1-byte E5 or 2-byte half effect of each typed source store. The native whole-grid result proves every byte at the returned physical pointer, the entire exterior byte frame, and every original input backing byte. Ordinary allocation and output-view facts are metadata-only boundaries; there is no host/allocator implementation, compiler binding, lowered-program callback, whole-output accuracy assumption, or exact-native-to-Real law. The deferred native numerical ports are individual scalar instructions/conversions and one fixed m16n8k8 TF32 MMA output lane.

The in-file `get_freq_multi_tokens` and `rbe_triton` helpers are retained. `Proofs/KernelRawRotary.lean` exposes the current `rbe_triton_transform` selected source and reuses its Real/native kernel results for their independent 128-period rotation; it labels the older source-only alias as a historical bridge. They are not called by the single-projection wrapper. Their integer widening, neighbor strides, masks and quotient/remainder ceil division are preserved in the actual source and checked separately.

Validation evidence is collected with targeted workspace-overlay Lean builds, public axiom audits and non-circular target audits. `check_source.py` executes 26 actual-wrapper/main-kernel CPU cases, checks 15 rejected calls, and runs four additional actual in-file rotary-helper cases. Checks cover original RMS conversions, tails, offsets, empty dimensions, same-base/same-dtype aliases, singleton strides, complete stores, and full input backing preservation. Alias controls admit same-base weight windows with distinct offsets and reject overlapping DLPack-imported backings with shifted base pointers. `check_lowering.py` records 16 main SM80 profiles (both storage formats, rotary on/off, i32/u32/i64 and constexpr-one signatures) plus four in-file raw rotary profiles. These are explicit `ASTSource` offline signatures, not a runtime binder trace. There is no GPU execution or native numerical-conformance claim.
