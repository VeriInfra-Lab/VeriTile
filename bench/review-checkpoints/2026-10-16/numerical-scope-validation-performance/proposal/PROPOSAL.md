## Concrete change

`validate_used_numerics` currently validates deferrals, derives the entire exact numerical authority, compares required callback names, validates explicit callback references, and validates every used theorem/case/port. A row that omits one deferral but still references it therefore pays the full authority cost before rejection. The existing `test_next_batch_required_port_omissions_are_rejected` repeats that pattern for every omitted port.

C extracts the existing callback-reference loop into `validate_callback_scope_references` and runs it immediately after the unchanged `validate_deferrals`. The helper checks the dictionary/list/reference shapes, nonempty lists, duplicate references, membership in already validated deferrals, and the callback's membership in that deferral's registered callback list. It returns the same callback-to-binding-key sets as the original loop. There is no new numerical assumption, normalized reference, data cache, exception suppression, or successful early return.

The required callback-name equality remains after `validated_exact_requirements`. So do the exact scalar-port checks, declaration/dtype/configuration checks, all required numerical IDs, and both complete-used-binding and complete-used-link equalities. Default call signatures, imports, CLI behavior and return values are unchanged. `exact_scope_gate.py` and all source authority derivation/queue validation code remain byte-for-byte unchanged.

Every successful call using exact numerical side tables still enters the real `validated_exact_requirements` path once. That unchanged path derives authority, collects legacy authority and validates the exact queue on every call. The historical nonexact/legacy path still calls that gate once and may return an empty exact table without derivation, exactly as before. Neither C nor A+C adds authority acceptance caching across calls.

A+C composes C with the frozen A changes: function-local rule-hash/binding indexes and declaration/case lookup indexes. The A component was reconstructed from its frozen generation script and its extracted functions were checked against the frozen A artifact. The full combined file was constructed directly from the same pinned original, not by applying patches to the checkout.

## Acceptance and error ordering

For ordinary immutable JSON input, write D for deferral validation, E for source-derived exact authority validation, N for required callback-name equality, R for local reference validation and U for all exact/usage checks. Original ordering is D,E,N,R,U. C uses D,R,E,N,U. R reads only the validated D result and the row's callback references; E and N do not supply values R needs or mutate these inputs. Thus the successful conditions are the same conjunction, while failing rows can stop earlier.

A alone preserves existing error ordering; the differential tests compare complete returned/error results with baseline. C intentionally changes rejection priority when several conditions are invalid. Examples include a missing deferral reference combined with invalid source authority or a stale queue, or a callback name that is both unexpected and incompatible with its reference. The candidate can report the local reference error before the old authority/name error. It still rejects. This proposal does not claim bit-identical errors for multiply-invalid inputs. Existing malformed unhashable IDs still raise TypeError; this patch does not broaden or repair the current input schema.

No acceptance follows from the queue merely looking internally consistent. With valid local references, stale queues, wrong public statements, unsupported configurations, missing roots, missing required callback names, omitted exact ports and unused extra links still reach and fail the unchanged downstream gates. Removing both a deferral and its callback link does not pass the check: exact-case-port validation still rejects it after authority validation.

## Bounded evidence and limits

The main suite runs baseline, reconstructed frozen A, standalone C and A+C through production `validated_exact_requirements`, `validate_exact_queue`/`extend_queue`, and `validate_exact_case_links` functions extracted unchanged from their pinned sources. Fixture providers replace only the expensive source derivation and legacy collection. Their counters show exactly one derivation/queue-validation path for each successful exact-queue call, repeat entry on successive calls, and rejection when a later authority provider fails. These are meaningful control-flow and acceptance/rejection tests, not a real full source-authority rebuild or a timing result for it.

The additional edge suite checks the legacy nonexact path, unchanged precedence of invalid deferrals, malformed unhashable IDs, and an extra callback name whose local reference is compatible but which the source-derived name check must reject.

The production-row suite reads the pinned shipped gzip queue and extracts the unchanged `usage` generator from the current production regression test. Its authority-shaped rule list excludes legacy rows without `scope_bindings`, because that original generator expects only exact authority rows. It tests the actual next-batch omission rows. An explicit sentinel replaces full derivation: candidate omission rows must reject before reaching it, while valid-shaped rows must reach it. Baseline and A are compared at the sentinel for one omission per table. These checks establish fast rejection on real row shapes; they do not establish production acceptance or revalidate the full source/receipt closure. The first harness attempt failed because the whole shipped queue also contains legacy rules without `scope_bindings`; its exact source/log/exit are retained. No candidate implementation changed in that repair.

Before integration, root should run the full existing production regression suite against a separately prepared combined candidate after the ongoing batch commits, plus representative positive exact usages with the actual source authority. Tests should retain the old multiple-port negative cases and add explicit call-order assertions, a repeated-call stale-authority test, and one example documenting changed error priority. There is no claimed wall-clock speedup until that separate production run is measured. The bounded evidence reports avoided authority entry counts, not estimated seconds saved.

All inputs, candidate sources, diffs, exact attempt logs and report files are pinned in the receipt. All local writes remain under this /tmp package. No full authority derivation, global verification, Lean build, GPU/native execution, repository application or commit is part of this proposal.

## Recorded bounded results

The main and edge suites passed 34 scenarios with 132 function executions across baseline, A, C and A+C. The shipped-queue suite covered seven declaration tables and all 15 omitted-deferral rows from the existing next-batch test: 30 fast rejection executions, 28 valid-shaped authority-entry checks, and 14 baseline/A omission entry comparisons. Total bounded function executions were 204. The shipped queue has 273 rules and 22,875 declaration cases; its compressed bytes remained unchanged. The production-shaped harness took about 112 seconds including repeated queue serialization and row validation; this is not an end-to-end performance measurement.

AST checks separately confirm that C changes only validate_used_numerics plus the new helper; A+C additionally changes only validate_deferrals. Both retain imports, top-level statements, default signatures, one authority-gate call site, one exact-case-link call site, the two final usage equalities and the return statement. The helper's reference loop AST is exactly the extracted original loop.
