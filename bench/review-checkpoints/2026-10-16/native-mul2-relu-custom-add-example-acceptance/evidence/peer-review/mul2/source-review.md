## Closure of the three previous blockers

**Access ownership:** `FiniteMemory.AccessContext` supplies read/write permissions per actual address and current launch device. `ByteRegion.device` retains allocation owner metadata and is no longer used to authorize accesses. `loadTile` checks every active input byte in the translated span through `AccessContext.Readable`; `tileWrites` independently checks every actual output byte through `Writable`. Thus accessible peer memory and pinned host memory are representable, while local ownership does not itself grant permission. No pointer, permission or ownership property is placed in the numerical queue.

**Actual extracted pointer and backing aliases:** `Runtime.pointers` returns `PointerSetup`, including actual argument pointers, translated allocation bases and one shared `AccessContext`. `PointerSetupBinding` binds its launch device, both extracted views, and the same Tensor object's identical extracted view. For nonnull raw pointers, `PointerBinding` connects pointer offset, finite extent and each translated byte to the original Tensor backing coordinate. A raw null pointer only requires the extracted pointer to remain null; it imposes no unused mapping/access premise. This matches installed `extractPointer`'s null bypass and CUDA-returned `DEVICE_POINTER` replacement. The exact driver and CUDA contract reviewed in v1 remain unchanged.

Kernel arithmetic uses the extracted pointers, signed i32 offsets and u64 wrap. `deviceMemory` resolves each loaded device byte through the shared address map into canonical backing memory. Stores retain `deviceAddress` and `outputAddress`; `tileWrites` checks that every actual byte resolves to the backing byte it writes. New `launch_write_resolution` proves this for every successful emitted store. The ownership set uses canonical backing bytes, so different aliases cannot evade duplicate-owner observation. Grid execution carries the updated canonical memory forward, so a later load through the same device alias sees earlier stores. The public result contains both independent byte last-write equality and actual-to-backing store resolution; the frame remains on original backing memory. Callback results contain address/access metadata only, never loaded values or final memory. The host still returns the original Tensor in place, preserving owner/device/data-pointer metadata despite a different CUDA argument pointer.

**B=1 signed-minimum grid rejection:** All 26 missing dtype/wrapper cases now exist. `host_grid_threshold` proves the exact signed-parser threshold for every positive integer block, and `i32_minimum_grid_boundary` distinguishes B=1 rejection from B=2 success. `launchWith` checks `gridFits` before calling `Runtime.pointers`, so a pointer error cannot precede the grid parser error. The table partitions every valid power-of-two block through 2^20 over all four size classes. The n=2^31 all-masked theorem remains unconditional once a launch is actually reached; the 20 larger block powers fit the parser and need no value or byte-access premise.

## Scope and preserved correspondence

The original Python and both seven-statement AST lowerings are unchanged. The scalar module, AST interpreter module and whole-grid module are byte-identical to v1. Signed/unsigned storage-width multiplication and bool raw-byte 0/2 stores remain concrete; only fp16/bf16/fp32/fp64 storage-width multiplication uses numerical callbacks. All loaded bit patterns are included. Existing source i32 narrowing, per-operation wrap, signed mask, u64 arithmetic and full active-tile-load-before-store behavior remain present. Every host schedule is a permutation of all launched pids exactly once, including in-place execution. Repeated programs are not native schedules.

Both wrappers retain their source order: outplace zeros_like, numel/cdiv, runtime preparation, signature/architecture handling, block validation, backend/context setup, signed grid parser, pointer extraction, positive launch, source grid and return. Inplace omits allocation. Successful zeros_like metadata, fresh identity, offset/extent, zero bytes and allocation frame remain unconditional. Empty launches still perform pointer/native setup and then access no bytes. Complete unsupported dtype and arbitrary Python integer block routes are retained. Access/missing-byte/ownership outcomes remain interpreter observations without claims about native exceptions, race winners, rollback or failure memory. The native environment is the frozen sm90/Triton 3.7.1/debug-false profile.
