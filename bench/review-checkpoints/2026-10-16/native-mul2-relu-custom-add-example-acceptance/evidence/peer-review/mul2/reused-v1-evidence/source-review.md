## Blocking findings

1. **Storage ownership is incorrectly used as device accessibility.** `FiniteMemory.lean:32–35` requires `r.device = some current` for both readable and writable memory. `FiniteHost.lean:54–61` sets that field from the Tensor's device. In the installed original runtime, `JITFunction.run` uses the current CUDA device/stream and does not switch to the Tensor's device. The exact installed `extractPointer` calls `data_ptr()` and asks CUDA for `CU_POINTER_ATTRIBUTE_DEVICE_POINTER`; it never inspects `Tensor.device`. CUDA's installed header explicitly permits UVA pinned host allocations and peer GPU allocations after peer access is enabled. Therefore an in-place host-pinned Tensor or an accessible Tensor owned by a peer GPU can pass original pointer setup and perform safe active accesses, while this model reports `inputAccess`. The out-of-place peer GPU route is affected as well. Access permissions must describe actual launch-context accessibility, independently of ownership metadata. Preserve the returned Tensor's original device metadata.

2. **The actual translated launch pointer is discarded.** `Runtime.pointers` returns `Except String Unit`, after which `layout` uses the original Tensor `dataPointer` and original byte-region addresses. Installed `extractPointer` writes the CUDA-returned device pointer back into the kernel argument. CUDA documents disjoint host/device aliases for registered host memory and write-combined host allocations. An active in-place source route can therefore execute at a distinct CUDA address. The revised ordinary runtime boundary should return the actual extracted argument pointers and connect them to accessible byte spans/alias backing; it must not return arbitrary result values or final memory. Merely deleting the device-equality predicate does not repair translation. Ordinary UVA CUDA allocations and peer allocations retain identical pointer values, as CUDA explicitly guarantees. Thus this blocker is specific to the broader mul2 source domain and is not evidence that a CUDA-only success domain must have nonidentity pointers.

3. **The exact case table omits the B=1 signed-minimum grid rejection.** `validBlock 1` holds and B=1 belongs to `other_valid`; at `n=2^31`, Python cdiv yields grid-x `2^31`. The native signed `i` grid parser rejects this value before pointer extraction. The Lean `gridFits` branch correctly models that rejection, but `propose.py:44` adds `grid_parse_rejected` only for `size_class=wide`, omitting `i32_minimum/other_valid`. All 13 admitted dtype routes and both wrappers are missing this case: 26 additions if retaining the current coarse block classes. The size argument itself is accepted and cast to `-2^31`; do not confuse its `extractI32` behavior with the distinct signed grid parser. Preserve the valid all-masked n=2^31 launch for larger blocks.

## Source correspondence and limits

`FiniteScalar` follows literal-left `2*x`: bool raw byte comparison against zero, i32 multiplication, raw-byte 0/2 store; signed/unsigned multiplication modulo storage width; storage-width fp16/bf16/fp32/fp64 multiplication with exact IEEE words for 2. Only those four floating multiplication operations are deferred; no integer, Boolean, conversion, indexing or allocation assumption is deferred. fp8 e4/e5 frontend arithmetic generates backend LLVM failures, fnuz rejects at architecture preparation, five complex/other formats reject signatures. All 22 canonical dense storage dtype routes are represented.

`FiniteMemory` narrows annotated length and each index operation to i32, uses signed masks, sign-extends offsets and wraps u64 pointer arithmetic. The n=2^31 theorem is universal over every lane, even wrapped indices. `FiniteSource` checks both original seven-statement ASTs and the register/pointer/mask links before executing the load/multiply/store tail. `FiniteProgram` completes active tile reads before stores, observes missing bytes/bounds/permissions/ownership, concretely assembles/splits little-endian bytes, and claims no native exception, race winner, rollback, or failure memory. The accessibility and translated-address blockers above affect this correspondence at the host-to-layout boundary.

`FiniteGrid` carries memory between programs and independently reads last-write memory for later blocks. `RuntimeContract.schedules` requires a permutation of every launched pid exactly once; repeated in-place doubling is not an admissible host schedule. The public arbitrary-list launch equality is stronger than that host contract and does not loosen schedules. Successful results include a pointwise byte result and an exterior frame. No logical-stride elementwise formula is invented: source kernels use flat pointer prefixes.

`FiniteHost` preserves the two wrappers: zeros_like only out of place, numel, Python cdiv, prepare, binder/architecture, block check, backend/context, signed grid parsing, pointer setup, positive launch, source grid, returned Tensor. Empty grids still perform setup. Out-of-place zeros and frame plus original shape/count/dtype/device, offset zero, fresh identity, and observed preserve-format strides are unconditional; in-place returns the exact input object. Python integer blocks are modeled as zero/division failure, invalid/frontend failure or powers of two up to 2^20, with ordinary resource-dependent backend failures explicit. Target is the recorded CUDA sm90/Triton 3.7.1 debug-false profile; no GPU launches or native numerical validation were performed.
