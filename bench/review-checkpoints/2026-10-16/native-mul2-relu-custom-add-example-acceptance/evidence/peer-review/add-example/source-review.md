## Actual ABI pointers and ordinary memory

The physical view distinguishes actual extracted ABI pointer, native allocation base, canonical backing base and capacity. Raw tensor data_ptr is retained separately. The installed extractPointer may replace a nonzero raw pointer with CU_POINTER_ATTRIBUTE_DEVICE_POINTER; null raw pointers bypass that query. All successful views share one native-to-canonical translation and permissions are indexed by the actual current launch device. Allocation owner metadata imposes no owner=current-device assumption.

`TensorBinding` ties the actual view pointer to the extracted pointer. Its translation obligation is conditional on nonnull raw data_ptr. Independent regression witnesses show (1) a null empty tensor with nonzero storage offset and a real backing span needs no unused translated span, and (2) an actual ABI pointer of 8 can correspond to canonical 108 while the raw pointer is 4000. The second is a formal witness of the mapping contract, not a measurement of a live CUDA mapping.

`AllocationBinding.bindings` is required only when dtype admission, every environment setup stage and grid parsing succeed. A pointer-stage failure makes this obligation vacuous; a clean-axiom regression proves that fact without inventing an extraction result. Other allocation fields express ordinary freshness and zero/frame properties, not unconsumed pointer evidence.

Memory is a complete canonical backing-byte valuation. Reads obey a local dtype decode law, so they cannot depend on unrelated bytes; writes obey pure dtype encoding, store-byte and byte-frame laws. There is no absent-map-byte fallback and no arbitrary tagged-carrier roundtrip premise. Active source loads/stores check native alignment, finite native span, native allocation bounds, canonical bounds, current-device byte permissions, and within-word affine translation. `translated_load` and `translated_store_byte` connect those accesses to backing bytes. Runtime/MMU metadata and ordinary byte encoding remain the explicit primitive boundary, not whole-kernel result assumptions.
