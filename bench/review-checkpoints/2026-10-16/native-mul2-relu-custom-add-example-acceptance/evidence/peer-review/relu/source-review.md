## Actual pointers, byte accesses and returned memory

`PhysicalView` distinguishes canonical backing base, native device base, actual extracted argument pointer and capacity. `AccessContext` provides one shared native-to-backing map plus per-byte read/write permissions indexed by the current launch device. Tensor owner-device metadata is retained and does not grant or deny access. This permits accessible peer/pinned memory without an owner=current-device assumption. The pinned native `extractPointer` uses CUDA DEVICE_POINTER and can replace raw data_ptr; it bypasses the attribute call for null pointers. `PointerBinding` retains the raw pointer metadata, preserves null extraction, and binds successful nonempty argument pointers and bytewise backing translation. The mapping and ordinary primitive contracts contain no loaded values or final-memory results.

Every active load is checked for native alignment, finite/inbounds native span, permissions for each byte, canonical backing extent and within-word affine translation. Every actual store has corresponding width-four checks. `translated_load` and `translated_store_byte` connect these native accesses to backing bytes. An independent Lean example reads native address 8 through a nonidentity map to canonical 108 on current device 7, with explicit byte permissions. This validates the formal plumbing without claiming a live CUDA access test.

The independent result uses the last covering store found in the reverse write list; bytes untouched by a store come directly from the allocated initial snapshot. `gridFormula` samples initial input bytes independently of execution, and freshness/frame proofs justify that sample through any program order. Complete launch schedules are permutations of all pids, with the same full read applicability. Native pid bounds prove that only pid0 writes. The public result consequently retains arbitrary empty_like contents beyond the first tile rather than claiming a complete tensor ReLU. Input and exterior bytes retain the original memory. Source accesses outside the stated memory model produce an observation carrying the allocated snapshot; this is explicitly not a native exception, rollback, successful return, or final-memory claim.
