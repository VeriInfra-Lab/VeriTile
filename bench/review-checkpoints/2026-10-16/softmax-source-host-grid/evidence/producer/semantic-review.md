# Author semantic review

This is an author review for independent root assessment, not the required independent acceptance review.

`HostGridCore.run` is a recursive actual executor. `run_io` has a generic step premise internally, but all four concrete grid theorems discharge it with existing `original_all_io`; callers of the public host theorem provide no execution or value oracle. Program setup resets registers and provides actual IDs/grid extents. State is threaded across every CTA, forward/backward stage, autotune trial, and final launch.

Output ownership is forward-inner row `r`, backward-inner row block `r/C`, and noninner column block `k/C` paired with row `r`. Coverage uses ceil division and modulo lanes. `owner_unique` and `noninner_coordinate_unique` prove the corresponding uniqueness arithmetic; the original per-program footprints supply the concrete write sets. `RunSafe` follows each actual intermediate state and every enabled original access is bounded by the respective allocation capacity. These are logical element addresses; no claim about native signed overflow is inferred.

The independent value references use initial-memory samples. Trials can produce different padding-dependent intermediate outputs; only the final selected launch's padding length appears in its reference. Trial frames preserve P,G and the arbitrary undef sampler. In particular the proof never zeroes inactive backward lanes. Aliased P=G is allowed; a contiguous already-saved gradient is its existing memory, not an independent overwrite. Fresh output/gradient imply X≠P, P≠Y, G≠Y. Arbitrary initial output contents and exterior memory are quantified.

The admitted theorem checks forward input storage, each attempted backward trial storage, and selected final storage. `checkedTrialRun_first_rejection` identifies the exact first failing choice after a successful actual prefix. Source-support premises are compiler-profile facts, not mathematical output facts. The separate erased helper deliberately has wider semantics and must not be advertised as source admission.

Metadata is source-composed through explicit ordinary Torch `LayoutPrimitives`: actual input strides feed contiguous conversion, its resulting strides feed fresh output empty_like, and those output strides feed backward empty_like. An observed positive-shape counterexample disproved a draft assumption that every fresh output has canonical singleton strides; the final theorem does not use that assumption. These metadata-only callbacks are within the trusted ordinary primitive boundary and are separate from kernel value execution.

The shape arithmetic uses original prefix-product M, selected N and `shape.prod/M/N` K; a lemma derives the suffix product only when M,N are positive. Invalid dims and zero divisors remain observable. K=0 is not rejected by a fabricated guard. Its unsafe inner launch is demonstrated both by a Lean equality to the K=1 launch and original AST metadata probes. Fresh allocation and contiguous-copy implementation are trusted ordinary primitives; the host probe checks source argument/result wiring with Torch metadata.

The finite source frontend probes compare exact function/helper body ASTs. The autotune probe preserves decorators too, uses the installed actual runtime methods, and propagates the real CompilationError from original-body IR generation. Synthetic timing selects 1024 only in successful cold routes, making the distinction between all trial attempts and final selection explicit. Frontend generation is not native backend or GPU validation.

Numerical scope is intentionally unchanged: dtype erasure cannot establish rounded mixed-dtype softmax equality. Existing FPEquiv concerns original/candidate equivalence and does not fill this value gap. Proposed future numerical work is operation/profile/source-bound in the remaining-work artifact, and no false zero-padding or cast identity is registered. Source success, source rejection and unsafe source behavior are separate outcomes throughout the review.
