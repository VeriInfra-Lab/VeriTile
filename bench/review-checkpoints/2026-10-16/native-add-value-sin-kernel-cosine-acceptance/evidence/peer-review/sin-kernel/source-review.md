## Exact source and dtype scope

I read the original Python, all eight proposed modules, the installed shared finite arithmetic, the proposal/adapter and pinned runtime evidence. Independent AST comparison checks that all native and wrapper probes use the original production definitions. The original kernel's seven statements are preserved. NativeSource lowers the existing Lean source AST, executes its finite index/mask prefix, and extracts its scalar expression from the actual sine instruction. The get proofs exclude unsupported lowering; there is no fallback instruction stream. The load/sine/store suffix and retained fp32/fp64 precision are separately proved.

The source execution uses sourceActiveTile and sourcePointer derived from that prefix. The independent plan uses separately defined wrapped requests. source_active_tile and source_pointer connect them. Each program loads its entire active tile before the scalar computations and stores. The two successful raw IR graphs have exactly one same-width masked input load, math.sin at that width and one same-width masked store. No implicit narrowing occurs on the fp64 path.

All 22 installed dense dtype profiles are classified: five binder failures, two fnuz architecture failures, thirteen sine-type failures, and fp32/fp64 backend successes. Fresh native records reproduce this matrix, and a separate clean-axiom theorem checks those exact observed records against the Lean admission classifier. An additional actual JIT binder run over all 22 real empty CPU dtype tensors agrees with the signatures used by the frontend probes: seventeen bind, five fail, and the n=1 signature remains i32.

The existing original source, mathematical, floating, candidate, execution and precision proofs remain unchanged. Eleven retained source/proof/document files were independently hash-checked. The additive modules do not replace those previous results with numerical validation claims.

## Host order, all extents and setup failures

The original wrapper reads x.numel before empty_like(x), then forms the BLOCK1024 grid, launches and returns the identical allocated output. It has no CUDA assertion, dtype guard, rank guard or contiguity requirement. The source host trace preserves this order even on allocation failure; an independent Lean regression checks the query-before-allocation failure trace. Eighteen original-wrapper AST traces with explicitly instrumented ordinary primitives reproduce query, allocation failure/success, launch arguments and object identity.

Tensor metadata retains actual shape, strides, storage offset, raw storage/data pointers, output preserve-format strides and owner device. Rank zero has numel one. Empty, transposed, sliced, broadcast and offset views are included. Seventy-five fresh CPU/launch-recorder cases all return actual empty_like allocations and the identical recorded output object. Their 150 tensor metadata records and semantic launch fields agree with the frozen evidence; allocator addresses and Python object ids are retained but excluded from cross-process equality. Fresh nonempty allocation intervals were checked. The empty-million-element-offset view remains null despite retaining backing storage.

Host numel spans the nonnegative signed64 domain. Native N stays annotated i32 at every extent, including n=1. Python grid size uses the original host value. Lane multiplication/addition wraps in 32 bits, comparison is signed, and pointer offsets are sign-extended, scaled by four or eight bytes and added modulo 2^64. Negative and repeated requests are retained rather than replaced by Nat-prefix indexing. A clean regression checks an actual source-derived negative offset and wrapped pointer re-entry.

Independent symbolic proof establishes the exact grid limit n <= (2^31-1)*1024. Fresh binder/packer/frontend/backend replay covers both successful dtypes at fifteen boundary extents, including empty, first tile, signed/unsigned wrap, grid threshold and signed64 maximum. The exact installed C extractor agrees at fifteen boundaries. Seven exact C grid-parser probes establish that an oversized signed-int grid fails before an instrumented downstream pointer failure. No CUDA context or pointer query is entered by those C tests.

The host model preserves JIT current device/stream, dtype admission, compilation, native context, signed-grid parsing, pointer packing and launch failure order. Its failure primitives cannot supply input values, a final kernel result or source execution. Empty and all-masked launches still traverse setup, then return the same allocated tensor and unchanged memory without input access/value or no-wrap premises. The all-masked theorem is independent of scalar sine values.

## Mapped pointers, raw words and memory frames

Torch storage/data addresses are distinct from actual extracted ABI pointers. Buffer.base/data describe the mapped allocation and pointer in the current launch address space; the memory byte function uses those coordinates. The model does not introduce an additional native-to-canonical toBacking map, and this review does not claim a separate canonical-address conversion theorem. The explicit ordinary boundary is truthful mapped allocation metadata and the actual successful extraction result. Owner device is retained separately and does not impose owner=current-device equality. Read/write permissions are indexed by the actual current launch device.

On unentered or failed extraction branches, unused total pointer fields may have ordinary affine completions and do not assert extraction success. Successful branches use actual extracted pointers. Independent clean regressions witness an empty CPU tensor with storage offset one million and a null data pointer, and a nonidentity mapped pointer: Torch raw data 116, actual launch pointer 16, mapped base 8, storage offset two, owner device one and readable current device zero. These formal witnesses check the contract's applicability, not live CUDA mapping behavior.

Memory uses optional bytes, with no missing-byte default. WordMemory ties each successful typed load to exact little-endian decoding and every store byte to the same-width concrete BitVec32/BitVec64 word. It cannot supply a sine result. Independent regressions check exact little-endian decoding, a missing byte remaining absent, and low/high fp64 byte extraction. Ordinary store/frame laws replace any need for an arbitrary-carrier readback axiom.

The independent result samples initial input memory. Fresh output and load/frame lemmas justify that snapshot through previous stores. Source access, missing-byte, output access and ownership issues remain mathematical observations; they imply no native exception, race winner, rollback, return or post-failure memory. The generic internal undefined-expression constructor cannot be produced by the total sine expression, as source_total and an independent compiled-scalar totality regression establish.

Schedule n carries an arbitrary permutation of every launched program id. The public host and grid theorem quantify over this schedule; no increasing native order is assumed. A regression derives Nodup from completeness, and another checks all-masked unchanged memory for arbitrary complete schedules. Every active request is examined. The owner ledger checks overlapping byte spans before claiming a returned value. The result retains the reverse-last-write raw-byte formula, untouched allocator bytes and the complete output exterior/input frame. An independent overlap/untouched-byte example checks the general raw-byte formula without claiming successful return for ownership-conflicting execution.
