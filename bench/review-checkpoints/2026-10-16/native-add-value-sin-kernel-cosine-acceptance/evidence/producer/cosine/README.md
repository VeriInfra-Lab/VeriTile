# Cosine finite source proposal

This temporary package preserves the existing cosine work for independent root review. It changes no repository or frozen package and confers zero acceptance. The user now requests Real, FP32 and BF16 as the default three lines plus original-program-required types. Root must separately map that checklist; the already-built wider dtype evidence is retained without further dtype expansion.

The public statement is `CosineNative.cosine_native_source_outcomes`, in nine new modules under `after/bench/tritonbench_g/cosine_compute`. Existing cosine proofs are unchanged and unimported by this native chain. The FP32 line uses native `math.cos`/libdevice `__nv_cosf`; the BF16 line loads BF16, converts to FP32, applies that cosine, then stores BF16. FP64 also explicitly narrows to FP32 before cosine.

The model translates the original five kernel statements into task-local syntax and proves lowering to finite execution and an independent initial-memory formula. It uses wrapping i32 offsets, signed masks, sign-extended wrapping u64 pointers, exact raw little-endian word memory, complete byte frames and every complete schedule permutation. Actual Torch storage, data and extracted pointers remain distinct; unused total fields do not imply successful extraction.

The wrapper allocates before querying numel or performing host math. N=0 computes BLOCK=0 and fails at cdiv(0,0), after allocation. N=2^31 computes BLOCK=65536 and grid=32768; successful setup returns the allocated tensor with unchanged memory because every signed mask is false. Native first rejection is binder, then architecture/type, then oversized i32 BLOCK scalar, then arange tensor size. Grid parsing precedes pointer packing, but huge cosine blocks fail compilation before any grid-limit counterexample can execute.

Host math uses pure finite integer computations for nearest-even binary64 conversion and correctly rounded square root, represented-value ceil and Triton's six shifts. Native CPython conversion and math.sqrt/libm conformance are **explicitly unvalidated** under the pinned current FE_TONEAREST environment. The 210,943 samples are nonexhaustive evidence. Both host conformance ports bind every one of the 246 post-allocation cases, including zero and subsequent binder/architecture/block/setup errors. The 22 allocation failures have no host ports. Kernel numeric correspondence is also deferred: 42 exact operation bindings across the already-built 15 admitted dtype paths. Total: 268 cases, 534 bindings, 17 numerical families.

Evidence includes 15 offline backend compiles, 220 already-recorded admission profiles checked by Lean, 15 backward SSA store-to-load paths, 86,016 compiled-C pointer comparisons, 21 inherited actual i32 extractor profiles, 23 original wrapper traces, six small CPU metadata examples and seven direct C parser tests. No GPU kernel ran and no large tensor was allocated. Inherited driver evidence is labelled as inherited, never as an independent cosine review.

`evidence/source-review.json` documents source and trust boundaries. `evidence/numerical-authority-delta.json` and the fail-closed `authority_adapter.py` are proposals requiring root-pinned producer and independent review receipts. The synthetic authority fixture checks whole-queue equality, all 534 omitted binding mutations, changed native/host evidence and producer self-review rejection; it is not approval. All failed compilation and script attempts are retained, including the corrected mutation-audit harness and proposal schema mistakes.

Reproduction uses the existing `/tmp/veritile-lean-toolchain` and the package's `compile.py`, `rebuild.py`, `check_recorded_admission.py`, `propose.py` and `check_authority.py`. `freeze.py finalize` writes the immutable receipt only after source, object, dependency and final clean-build checks pass. Do not edit after that receipt exists.
