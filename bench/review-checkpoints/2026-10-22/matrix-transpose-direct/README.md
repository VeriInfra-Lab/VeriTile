# matrix_transpose：直接使用 triton 定义

`Kernels.lean` 的原程序和候选现在都直接写成
`def ... : ComputeKernel := triton { ... }`，移除了外层手工重建端口的
`ComputeKernel.mk ... (...).surfaceBody`。

DSL 的端口元数据现在跟踪中间指针的静态来源，并在实际 load/store 时
收集对应区域；仅构造地址不会把输出区域登记成输入。此改动不涉及指令生成、
精度、数值语义或输入契约。两个完整 kernel 函数与修改前定义的相等性
均由 `rfl` 检查，包括输入输出端口和完整语句。

定向构建、两个主入口的源码检查、指针端口回归、运行标量和完整精度测试均通过。
端口回归覆盖直接地址、中间指针链、仅构造地址、重赋值、指针递增递减、
分支及循环内使用，并检查完整转置 kernel 的两个端口。

附带的 `TritonSmoke` 检查被当前依赖对象中缺少 `Op.minimumFloat` 拦住。
隔离换回修改前的 Metadata 后，同一检查仍出现相同错误；因此没有把广泛 smoke
记为通过，也没有在本次格式整理中重建整个核心依赖集合。

完成分类和数值规则保持不变；没有进行 GPU 实测或独立全源码回放。
主入口源码本轮未改动；本次直接编译检查同时刷新了此前已过时的 Correct 源码哈希。
精确源码、检查和证据引用见 [audit.json](audit.json)。
