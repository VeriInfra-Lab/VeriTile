## 确认的问题

- 整段 kernel 由题目自定义宏、前端或生成器拼装，原程序和候选不能直接逐行阅读。
- 用零值占位赋值登记运行标量，再通过 drop/tail 删除语句。实际参数虽然另有绑定，呈现仍不清楚。
- 通过手写语句 AST、列表切片、替换或递归拼接构造实际执行的 kernel。
- 权威源码放在 Proofs，源码入口反向依赖证明模块；或可选结果混入主证明必需模块。

各项的当前具体位置、实际 IO 使用链及受控修法见 [audit.json](audit.json)，完整原始观察在引用的分组报告。同一题可能有多种问题，类别数不能相加当作题数。

初查时，`adam_update_triton`、`attention_llama` 的简单 tl.param 替换未通过完整 AST 身份检查，因此当时未应用；后续完成须另有完整源码或语义连接，具体状态以逐题清单为准。
